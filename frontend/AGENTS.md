# AGENTS.md

## Project Overview

Frontend admin panel built with [Refine](https://refine.dev) v5 — a React framework for CRUD apps. Scaffolded from `create-refine-app` (single initial commit). Stack: React 19, TypeScript, Vite 6, Ant Design 5, React Router 7, Refine DevTools.

The Python backend lives in `../backend/` (FastAPI: serves this build, redeems invites, exposes `GET /config` and the session-key-authenticated `GET /models` — see the root `AGENTS.md`). Both the **auth** and **data** providers talk to a real LiteLLM proxy (default `http://localhost:4000`, overridable at runtime — see `providers/config.ts`). The Python backend integration is wired: the `/invite/:team_id/:invite_code` page redeems invites through it, and startup `GET /config` adopts its runtime `LITELLM_URL` + app version.

## Commands

```bash
npm run dev      # dev server (wraps `refine dev`)
npm run build    # typecheck (tsc, noEmit) THEN vite build via `refine build` → dist/
npm run start    # serve production build
npx tsc --noEmit # typecheck only (the same gate that runs first in `npm run build`)
npx eslint .     # lint (see gotcha below — there is NO `lint` script in package.json)
```

- No test framework is configured. There are no tests and no test runner.
- **Never start the dev server yourself** (`npm run dev`) — the user keeps one running. Typecheck with `npx tsc --noEmit` instead of smoke-testing in a browser.
- `.npmrc` sets `legacy-peer-deps=true` — use npm; dependency resolution expects it.

## Architecture

Standard Refine composition, all wired in `src/App.tsx`:

```
BrowserRouter → RefineKbarProvider → ColorModeContextProvider → AntdApp → DevtoolsProvider → <Refine>
```

- `src/providers/data.ts` — **LiteLLM data provider** mapping Refine resources to proxy endpoints: `keys` (`/key/list|info|generate|update|delete`, id = `token` hash), `teams` (`/team/list|info|new|update|delete`, id = `team_id`), `users` (`/user/list|info|new|update|delete`, id = `user_id`), `models` (**read-only**, `/model/info`, id = `model_name`; create/update/delete throw). Pagination: keys use `page`+`size` (size hard-capped at 100), users `page`+`page_size` (cap 100) — both server-side with `total_count`/`total`; teams and models return the whole list in one call (sort/filter applied client-side via `applyClientSide`). Sorters map to `sort_by`/`sort_order` (keys, users); `eq` filters map to server params (`KEY_LIST_FILTERS`/`USER_LIST_FILTERS`, e.g. `team_id`, `user_id`, `status` for keys; `role`, `team`, `user_email` for users). Response unwrapping: `/key/info` → `info`, `/team/info` → `team_info`, `/user/info` → `user_info`. `deleteOne(keys)` tolerates 404 "No keys found" as success (retry-safety for the delete→create regeneration flow). `custom()` is a passthrough to `litellmRequest`. **models `getList`**: for **non-admin sessions** (`!isAdminRole(loadSession()?.userRole)`, and no `keyHash` meta) it calls the Python backend's same-origin `GET /models` instead of the proxy — same `{data}` shape but master-key-fetched (the proxy hides deployments **and pricing** from internal users) and filtered to the teams the signed-in user belongs to, with `meta.teamId` forwarded as `?team_id=`; on any backend error it falls back to the direct `/model/info` flow (bare dev server without the Python backend). Admins keep the full direct catalog; `meta.keyHash` (key's own allowlist) always uses the direct flow. Response shapes verified against live proxy v1.100.x — the OpenAPI spec leaves most of them untyped; the field-level semantics live in this file.
- `src/providers/litellm.ts` — thin API client: `litellmRequest(path, {method, query, body})` fetches with `Authorization: Bearer <session api_key>` (JWT `key` claim from `session.ts`; no session → 401). Errors throw `LiteLLMError` (implements Refine's `HttpError` interface: `message` + `statusCode`) with the message extracted from all three LiteLLM error shapes; network failure → statusCode 0. A 401 reaching the app triggers `authProvider.onError` → logout.
- `src/providers/backend.ts` — same-origin client for the Python backend (it serves this build in production): `backendRequest(path, {query})` sends the session's virtual key as Bearer so the backend can attribute the call to a user; same `LiteLLMError`/`extractErrorMessage` handling as `litellmRequest`. Used by the data provider's models `getList` (`GET /models`) and the team page's owner-name resolution (`GET /users` — the proxy's `/user/list` is admin-gated and cross-user `/user/info` 403s, so members resolve teammates' aliases through the backend, restricted to co-members); in dev, `vite.config.ts`'s `inviteProxy` middleware forwards these paths to the backend **only when the request carries an Authorization header** — a headerless GET of `/models` is a browser navigation to the SPA route and stays on the Vite server.
- `src/providers/session.ts` — session/JWT utilities shared by auth + data providers: `decodeJwtPayload`, `sessionFromToken`, `loadSession`, `saveSession`, `clearSession`, `extractErrorMessage`, and `TOKEN_KEY` (`litellm_session`).
- `src/providers/auth.ts` — **real LiteLLM auth**: `login` POSTs `{username, password}` to `POST {API_URL}/v2/login` (endpoint hidden from the proxy's OpenAPI spec; default admin is `admin` + master key). Success returns a session JWT that is **decoded client-side, never verified** (`decodeJwtPayload`); the JWT's `key` claim is the virtual key used as `Authorization: Bearer` for API calls (the JWT itself is NOT accepted as Bearer unless the proxy enables `enable_jwt_auth`). Sessions persist as `{token}` JSON under the `litellm_session` localStorage key (`TOKEN_KEY`). `check` re-derives the session on every call and rejects missing/malformed/**expired** (`exp`) tokens; `getIdentity`/`getPermissions` return the JWT claims (`user_id`, `user_email`, `user_role`); `onError` logs out on any 401 (LiteLLM invalidates session keys unpredictably, e.g. after key-management calls). Error bodies are parsed with `extractErrorMessage`, which handles all three LiteLLM shapes: `{"error": {"message"}}`, `{"detail": "..."}`, `{"detail": {"error": "..."}}`.
- `src/providers/constants.ts` — `API_URL` (LiteLLM proxy URL; reads `VITE_API_URL` env with fallback `http://localhost:4000`, trailing slashes stripped) is only the **build-time default**; always read the URL through `getApiUrl()`, which returns the runtime override set by `setApiUrl()` when the backend's `/config` answered. The session storage key `TOKEN_KEY` lives in `session.ts` (and is duplicated here, unused).
- `src/providers/config.ts` — startup `loadServerConfig()` (awaited in `index.tsx` before the first render): same-origin `GET /config` (5 s timeout, dev-proxied by `vite.config.ts` to the Python backend, `INVITE_BACKEND_URL`, default `http://127.0.0.1:8000`) returning `{litellm_url, version}`; overrides the API URL via `setApiUrl` and stores the version for the footer (`getAppVersion()`, `null` when no backend answers — e.g. bare dev server).
- `src/providers/access.ts` — `accessControlProvider` hiding the admin-tier `teams`/`users` sider entries for `internal_user` sessions (`/team/list` and `/user/list` 400 for them). ThemedSider wraps every menu item in `<CanAccess resource action="list">`, so no custom sider is needed; everything else is allowed. Also exports `isAdminRole(role)` (allow-list: `admin`, `proxy_admin`, `proxy_admin_viewer`, `org_admin` — unknown roles count as non-admin) used by the data provider's models path and the models page title.
- `src/contexts/color-mode/` — custom light/dark mode context, persisted to localStorage key `colorMode`, wraps antd `ConfigProvider` with `RefineThemes.Blue`.
- `src/components/` — shared components, re-exported through `src/components/index.ts`. `ServerStatusBanner` ports the Alpine reachability strip: unauthenticated `GET {getApiUrl()}/health/liveliness` (5 s timeout, any HTTP response = reachable, only network errors = unreachable) with a Retry button; rendered above the `<Outlet />` in the ThemedLayout and above the card on the login page (not on the invite page — that flow targets the Python backend, not the proxy). `AppFooter` is the ThemedLayout `Footer`: repo link, `v<version>` from `getAppVersion()`, "Connected to `getApiUrl()`". `KeyRowActions` (the "…" menu on every key row) offers Edit (`/keys/edit/:id`), **Regenerate** (modal confirm, then simulated — LiteLLM's `/key/regenerate` is Enterprise-only: `POST /key/delete` of the old hash first — aliases are globally unique so the replacement can only take the old name once it is free, 404 "No keys found" tolerated as already-gone — then `POST /key/generate` with `buildRegenPayload` copying every attribute: alias, team, budgets (max/soft/duration/fallbacks), **spend**, models, aliases, config, metadata, permissions, per-model budgets/limits, tpm/rpm/parallel limits, cache controls, key_type, blocked flag, and remaining validity as `duration: "<n>s"`; `user_id`/`organization_id`/`allowed_routes` are only copied for admin sessions — internal users can't set those; the plaintext new key is shown once in a copyable modal), **Enable/Disable** (`useCustomMutation` → `POST /key/block` / `/key/unblock` with `{key: <token hash>}`; reversible so no confirm — then `useInvalidate` refreshes the keys queries, since `useCustomMutation` does not invalidate on its own), and Delete (modal confirm). Block/unblock are admin-tier endpoints: proxy/team/org admins only — internal users get 403.
- `src/pages/` — one folder per page (`login/`, `invite/`, `register/`, `forgotPassword/`), each typically an `index.tsx` wrapping Refine's `<AuthPage type="...">`.

**Routing (full app shell)**: authenticated routes render inside `<ThemedLayout Header={Header} Sider={ThemedSider} Footer={AppFooter}>` (sidebar driven by the seven `resources` in `<Refine>`: dashboard, keys, teams, users, models, playground, help — each with `list` route and a `meta.icon`; **dashboard, playground and help are menu-only resources** — no data-provider backing, their pages never issue a CRUD call on those names; teams/users are hidden from the sider for internal users by the access provider; `<ServerStatusBanner />` renders above the `<Outlet />`). `AppFooter` mirrors the Alpine footer: repo link, `v<version>` (from `/config`, hidden when absent) and "Connected to `getApiUrl()`". Routes: `/dashboard`, `/keys` (+ `/keys/edit/:id`), `/teams` (+ `/teams/edit/:id` — **team edit**: `useForm` on resource `teams`, fields Name / Max team budget / Team member budget / Allowed models (tags Select with `/model/info` suggestions, same as the key form) with the same validation as create; `getOne("teams")` flattens `team_member_budget_table.max_budget` into a flat `team_member_budget` field so the form syncs, and the Form's `onFinish` override converts cleared fields to explicit `null`s so `/team/update` clears the budgets instead of skipping them; entry points: an Actions-column EditButton in the list and an EditButton on the team detail card, redirect back to the list; the form also has an **Invite link** row — the current code shown copyable (copies the full `{origin}/invite/{team_id}/{code}` URL; "None yet" when unset) plus a Create/Regenerate button that immediately `POST /team/update`s a fresh 8-char `metadata.invite_code` merged into the existing metadata (independent of form save; server re-merges system-managed keys), refetches the record and shows the full URL once — regenerate confirms first since it invalidates the old link; generator in `src/utils/invite.ts`), (**create team**: header "Create" button opens an antd modal form — Name (required), optional Max team budget + Team member budget in USD (positive-only, `team_member_budget` is the NewTeamRequest field behind `team_member_budget_table.max_budget`), and a "Create invite link" Switch; submits `POST /team/new` via `useCreate` with `team_alias` and always `team_member_permissions: ["/key/generate", "/key/delete"]` (else members get 401 managing their keys), `metadata.invite_code` = 8-char crypto-random code when the toggle is on, and shows the full invite link once in a copyable success modal on creation), `/team/:team_id` (**team detail**: team card + "My virtual keys" filtered client-side to `identity.id`, then a "Team keys (all members)" table rendered only when `/team/{id}/members/me` returns `role === "admin"`; both tables share one `useList` keys walk with a permanent team_id filter; the team card shows the **invite link** — the invite code, hyperlinked to `{origin}/invite/{team_id}/{code}` with a copy button copying the full URL — but only when `team_info.metadata.invite_code` is set (same format the invite-redemption backend parses); the **Team owner** cell shows the admins' display names — alias from `/user/list` when the session may call it, else the backend's `GET /users` (see `providers/backend.ts`), email only when the user has no alias at all), `/users`, `/models`, `/profile`; `/` redirects to `/dashboard` (successful login also redirects there); `/login` bounces signed-in users to the first resource (dashboard); `*` renders `ErrorComponent` behind `CatchAllNavigate`. The `Register`/`ForgotPassword` page files exist but are unrouted and unused (LiteLLM OSS has no direct signup/password-reset — signup happens via invite links). The **Dashboard** (`src/pages/dashboard/index.tsx`) shows a stats row ("My total spend" / "My budget" from `user_info.spend` / `user_info.max_budget`), "My teams" (from `useCustom` → `GET /user/info?user_id=<identity.id>`, its `teams` array carries full team objects; the **My spend** column renders a `TeamMemberSpend` cell that calls `GET /team/{team_id}/members/me` per row — the user's own spend within that team, the same per-member number the official LiteLLM UI shows; `teams[].spend` is the whole-team total and must NOT be used; per-user-per-team spend also cannot be derived by summing key rows) and "My virtual keys" (from `useList` on `keys` with `meta: { allPages: true }`, **filtered client-side to `user_id === identity.id`** — server-side filtering breaks for env-credential admins whose user_id `default_user_id` matches no keys). Note Refine v5 hooks return `{ query, result }` — use `query.isLoading` / `query.data` — and `useCustom` takes params via `config: { query: {...} }` and returns the **raw response body** (no `{data}` wrapper, same convention as simple-rest).

**Invite redemption page**: `/invite/:team_id/:invite_code` (`src/pages/invite/index.tsx`, `InviteRedeem`) — the only unauthenticated route besides `/login`; the invite links built by the teams pages point here. It POSTs to its own URL (`window.location.href`), which in production is the Python backend serving this build (`POST /invite/{team_id}/{code}` — full contract in the root `AGENTS.md`). Signed-in visitors get an accept view (`Authorization: Bearer <session api_key>`, no body; team name + the member budget the new key will carry come from same-origin `GET /invite/{team_id}/{code}/info` on the Python backend — master-key validated, so it works for anonymous visitors too; best-effort, falls back to the raw team id). Anonymous visitors get two tabs: "Create account" (default) sends `{full_name, email, password}` as the POST body with no auth header, and "Sign in" POSTs `{username, password}` to `{API_URL}/v2/login` **directly, not via `useLogin`** — the Refine login flow would redirect to `/dashboard`, while here the session is saved and the page flips to the accept view without navigating. Success shows the returned plaintext `key` once (copyable, monospace — same pattern as the regenerate modal) and invalidates the `keys` list; server errors surface as inline Alerts via `extractErrorMessage` (409 "You already have a virtual key for this team" / duplicate email "sign in instead" come from the backend). Dev: `vite.config.ts`'s `inviteProxy` plugin forwards `POST /invite/*` and `GET /invite/{a}/{b}/info` to the Python backend (`INVITE_BACKEND_URL` env, default `http://127.0.0.1:8000`; 502 with a readable `detail` when it is down) — other GETs stay on the Vite server so the SPA route keeps serving the dev app with HMR.

**Playground** (`src/pages/playground/index.tsx`, `/playground`): port of the Alpine view — test a **user-pasted virtual key** (not the session key) with a free-text model name; non-streaming `POST {getApiUrl()}/chat/completions` sending the whole conversation each turn, Enter sends / Shift+Enter inserts a newline, assistant replies in monospace bubbles, errors via `extractErrorMessage` in an Alert, Clear-conversation button. **Help** (`src/pages/help/index.tsx`, `/help`): static port of the Alpine Help view — Python `openai` client example (interpolating the live `getApiUrl()`, computed at module load after `loadServerConfig()` has run) plus the budget-mechanism explanation (key spend/budget, team budget, team member budget, regeneration keeps spend).

**`src/pages/login/index.tsx` is a custom login page** (antd `Form` + `useLogin`), not `<AuthPage type="login">`: the bundled AuthPage hardcodes an email field with email-format validation, but LiteLLM usernames (e.g. `admin`, or DB users' emails) need a plain **username** field with no email-validity check. It sends `{username, password}` straight to `authProvider.login`; login errors surface as antd notifications via `useNotificationProvider`.

**List pages** (`src/pages/{keys,teams,users,models}/list.tsx`) use `useTable` from `@refinedev/antd`. Keys and users use server-side pagination (the data provider maps it); teams and models set `pagination: { mode: "client" }` since their endpoints return full lists. Keys columns mirror the Alpine app (Key = `key_alias ?? key_name` (LiteLLM's name fields), Owner/Team show **real names** — the data provider enriches each page of keys with `owner_name` (via one `/user/list?user_ids=a,b,c` call; alias → email fallback) and `team_name` (via `/team/list` for admins, then per-id `/team/info` which also works for team members; both best-effort, raw id fallback), spend/budget USD, expires (`DateField`, null = Never), blocked tag, models stub + per-row `EditButton`/`DeleteButton`). Keys have an **edit page** (`src/pages/keys/edit.tsx`, route `/keys/edit/:id`): Name, Budget (USD, empty = unlimited), Team (Select from `/team/list`, best-effort), Models (tags Select with suggestions; empty = all models). Saves via `POST /key/update {key: <hash>, ...}`; keys `getOne` looks records up by hash via `/key/list?key_hash=<id>&size=1` (NOT `/key/info`, which expects the raw key). Teams columns: Name, Keys (count), Team budget (max), Member budget (default), Spend (total), Allowed models (link to `/models?team_id=`; "All models" when null/empty — still carries the team_id), Invite link (code hyperlinked to `{origin}/invite/{team_id}/{code}` in a new tab + copy icon copying the full URL; `—` when unset), Actions (Edit); the data provider's teams `getList` **enriches** each `/team/list` row via `/team/info` in parallel (best-effort → null on failure): `key_count` = length of the response's `keys` array, `max_budget`/`spend`/`models` from `team_info`, `member_budget` from `team_info.team_member_budget_table.max_budget`, `invite_code` from `team_info.metadata.invite_code`. Models columns show per-Mtok pricing from `model_info.*_cost_per_token` × 1e6, plus a client-side free-text filter (name or `model_info.mode`); the page **requires** `?team_id=` or `?key_hash=` (every "models" link carries one, even "All models") — without a filter it renders nothing and fetches nothing (the resource is hidden from the sider). The title is `Models for team <alias>` (alias unresolved → the team id) for `?team_id=`, the key's alias + masked key + team for `?key_hash=`; non-admin sessions get the backend's team-filtered list with pricing — see the data provider above. Note: `/team/list` is **admin-only** — internal-user sessions get a 400 error notification there; same for `/user/list` style admin data depending on role.

## Conventions

- Feature-folder structure: every component/page/context is its own directory with `index.tsx`; shared components get an `index.ts` barrel re-export.
- React Router v7 import style: `from "react-router"` (not `react-router-dom`).
- Named exports for components (e.g. `export const Header = ...`), `export default App` only in `App.tsx`.
- Components are function declarations/arrow constants, not `React.FC` (exception: `Header` uses `React.FC<Props>`).
- Styles are inline `React.CSSProperties` objects + antd design tokens (`theme.useToken()`), not CSS files. The only global CSS import is `@refinedev/antd/dist/reset.css` in `App.tsx`.
- `strict: true` TypeScript; `tsconfig.json` covers `src/` (with `noUnusedLocals: false`), `tsconfig.node.json` covers `vite.config.ts`.

## Gotchas

- **`.env` now works but defaults are fine**: `src/providers/constants.ts` reads `VITE_API_URL` (fallback `http://localhost:4000`, the LiteLLM proxy) — override the proxy URL there. `.env` is gitignored.
- **ESLint is clean** (the scaffold's old unused-import errors were resolved by wiring the routes; only a benign `react-refresh/only-export-components` warning remains in `color-mode/index.tsx`).
- **Build gate order**: `npm run build` runs `tsc` first — type errors fail the build before Vite ever runs.
- Refine `projectId` (`11BTWd-s7WeyS-LOfTLO`) is duplicated in `package.json` (`refine` field) and `App.tsx` (`options.projectId`); it ties the app to Refine DevTools/telemetry.
- `frontend/Dockerfile` is the create-refine-app scaffold's standalone image (`refinedev/node:18`, serves `dist/` with the `serve` package as a non-root `refine` user; build context expects `package-lock.json` via `npm ci`) — **unused**: the published image is built by the root `Dockerfile` (multi-stage node+uv; see the root `AGENTS.md` for its current, post-move state).
